# Engine-feasibility review: plan rev. 1 against franken_manim HEAD `6043e68c`

**Scope.** I read the plan and the capability survey, then checked both against the code at HEAD `6043e68c`, which is also `origin/main`. File:line citations are relative to the franken_manim root unless a path says otherwise. I modified nothing in either repo. All cargo experiments ran in my scratchpad, using the pinned toolchain's real cargo binary directly, because the RCH shim refused a local build outside `<projects-root>`.

**What changed since the survey (`fb1c1b9e..HEAD`, 16 commits).** The authoring API is unchanged (`fmn-anim`, `fmn-mobject`, `fmn-scene`, `fmn-render` and `fmn-output` are untouched), with one exception: `ef0eddb2` repinned franken_markdown from `bd00a247` to `3ed1d332` (`Cargo.toml:51`). That brings three visible changes:
- **Tex submobject order** now follows TeX's emission order (fm-aia1).
- **TexText ligatures are disabled.** `--` now prints as two hyphens and `` ` ` `` as two left quotes.
- **New layout details:** `\scriptspace`, primes, and brace fills.

The Hoeffding import was verified only at `e2eec632`, which still used `bd00a247`.

## Experiments run

**E1: git dependency plus `--config` patch, with dummy crates.**
- **Setup.** Pinned cargo 1.100.0-nightly (`e8cb624d5`) from nightly-2026-08-31, with a fresh `CARGO_HOME`. A local git "upstream" mimics franken_manim:
  - `[workspace.package]` and path-based `[workspace.dependencies]`;
  - `default-features = false` and an `ffmpeg` feature forward;
  - a member with an `artifact = "bin:fmn"` dev-dep;
  - a malformed nested `Cargo.toml`.

  The downstream workspace declares `fmn = { git = "file://…", rev, features = ["ffmpeg"] }` in `[workspace.dependencies]`.
- **T1:** builds and runs, printing `fmn@git + core@git (process=true)`. The malformed manifest prints `error: unclosed table` but is skipped.
- **T2:** `--config 'patch."file://…/upstream".fmn.path="../franken_manim_wt/crates/fmn"'` gives `fmn@LOCAL-DIRTY + core@LOCAL-DIRTY`. Patching only `fmn` also moves its internal path deps. **Cargo.lock is rewritten** (the `source = "git+…"` lines disappear).
- **T3:** the same relative path, invoked from `explainer_corpus/demo`, fails: it resolved to `…/explainer_corpus/franken_manim_wt`, i.e. **relative to cwd**.
- **T4:** `--locked` with the patch fails with "cannot update the lock file".
- **T5:** `--config resolver.lockfile-path="<abs>/.x/fmn-local/Cargo.lock"` works and leaves the committed lock untouched. The pinned cargo says the key "is now always available"; a filename other than `Cargo.lock` is refused. A later `--locked` git-mode build then succeeds.
- **T8:** a relative `[patch]` inside `<root>/.cargo/config.toml` resolves against the workspace root from any subdirectory.
- **N1:** a `members` glob that covers a crate with its own `[workspace]` fails with "multiple workspace roots found"; `exclude` fixes it.

**E2: sizes.** For franken_manim itself, `.git` on disk is 281 MB with 3,206 commits, GitHub reports 37.7 MB, and the HEAD tree is 42.7 MiB (largest file `.beads/issues.jsonl` at 3.4 MiB). The FrankenSuite deps are listed in F-01. frankentorch (72 MB) is not in fmn's graph.

**E3: font cmap probe** (pure-Python parser over the bundled TTFs). ⊕ ≺ ⌊ ⌋ ≡ ⇔ ⋅ ∈ appear only in NotoSansMathSymbols. α, θ, ő and – are in CMU and IBM Plex. ✗ is in no bundled face. × is in Plex and Noto.

**E4: lock drift.** Hoeffding's `Cargo.lock` against franken_manim's at `e2eec632`: 261 common packages, 0 version mismatches.

**E5: level check.** `current.py:53` measures the pad with `* g(-9)`, while `nar.py` measures the raw narration files. That is the basis for F-11.

**E6: shallow fetch.** `-Zgit=shallow-deps` alone fails on a local transport ("shallow fetch is not supported by the local transport"). Adding `-Zgitoxide=fetch` produces a shallow db (`rev-parse --is-shallow-repository` returns true). I did not test this over https.

**Not run.** No franken_manim or Hoeffding build and no render, so the per-effect fps figures remain spike work. The one command I ran in franken_manim, `cargo tree --offline --locked`, failed because franken_markdown `3ed1d332` isn't cached locally; it wrote nothing.
